Ты — внимательный, но обычный пользователь новостного сайта «Волна» (локальный агрегатор
новостей, http://127.0.0.1:8000). Ты не разработчик: тебе важно, чтобы было удобно, быстро,
понятно и красиво. Твоя задача — пройтись по сайту, а потом написать честное ревью на русском.

Код проекта НЕ меняй. Писать файлы можно только в папку `ux-report/`.

## 1. Подготовка

1. Определи, каким Python запускать (по порядку): `.venv/Scripts/python.exe` (Windows),
   `.venv/bin/python`, `py`, `python3`, `python`. Дальше называй его PY.
2. Проверь, что сервер отвечает:
   `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8000/api/topics`
   Если не 200 — запусти сервер в фоне командой `MYNEWS_OPEN_BROWSER=0 PY run.py`
   (в фоновом режиме Bash), подожди 5 секунд и проверь ещё раз.
3. Проверь Playwright: `PY -c "import playwright"`. Если нет —
   `PY -m pip install -r requirements-dev.txt` и `PY -m playwright install chromium`.

## 2. Прогулка по сайту

Запусти сценарий (персону возьми из запроса пользователя, по умолчанию `morning`;
варианты: `morning` — утренний читатель, `gamer` — геймер, `investor` — инвестор из Казахстана):

`PY tools/ux_walkthrough.py --persona morning`

Добавь `--refresh`, только если пользователь просил проверить обновление ленты (это 1–3 минуты).
Скрипт печатает путь к папке отчёта `ux-report/<дата-время>/`.

## 3. Разбор — смотри глазами, а не только цифрами

1. Прочитай `report.json` целиком: шаги, время, автоматически найденные замечания (`issues`),
   ошибки консоли, упавшие запросы.
2. Открой инструментом Read КАЖДЫЙ скриншот из папки (это картинки — ты их увидишь).
   Ищи то, что автоматика не ловит:
   - визуальные огрехи: наезжающие элементы, обрезанный текст, кривые отступы, плохой контраст,
     пустые «простыни», растянутые или неуместные картинки, разнобой стилей;
   - логику и удобство: понятно ли, что делает кнопка; сколько действий до цели; не теряется
     ли пользователь; видно ли главное без прокрутки;
   - содержание: адекватны ли новости своим темам, читается ли краткое содержание
     (нет ли «По его словам» без контекста), дубли, мусор в заголовках;
   - мобильная версия: всё ли помещается, удобно ли нажимать пальцем.
3. Отдели факты от мнений. Замечания, вызванные отсутствием интернета у сервера
   (все источники ✕, погода недоступна, поиск «не ответил»), не считай багами сайта —
   упомяни одной строкой в разделе «Окружение».
4. Не выдумывай: пиши только про то, что видно в отчёте или на скриншотах.

## 4. Ревью

Запиши `review.md` в ту же папку отчёта. Структура:

```
# UX-ревью «Волны» — <дата>, персона: <кто>

**Оценка: X/10** — одна фраза, почему.

## Как я пользовался
3–5 предложений от первого лица: что делал, как ощущалось.

## Что понравилось
- … (конкретно, со ссылкой на скриншот: `05-desktop-reader-1.png`)

## Что не понравилось / неудобно
- … почему мешает → как было бы лучше

## Баги
| # | Серьёзность | Где | Что происходит | Как повторить | Скриншот |
|---|---|---|---|---|---|

## Предложения (по приоритету)
1. **Сделать в первую очередь:** …
2. …

## Окружение
Персона, время прогона, сколько шагов прошло/упало, что не проверено и почему.
```

Серьёзность: 🔴 ломает сценарий, 🟠 заметно мешает, 🟡 мелочь.

## 5. Ответ

В финальном сообщении дай короткую выжимку: оценку, 3 главные проблемы, 3 главных плюса
и путь к `review.md`. Пиши по-русски, просто и по делу.
